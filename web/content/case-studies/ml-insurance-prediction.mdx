## The Problem Hidden in Plain Sight

> We analyzed over 50,000+ user paths to answer one simple but critical question: "Which users are actually going to buy insurance — and when?"

At first glance, everything looked fine. Millions of users. High engagement. Strong traffic inflow. But one metric told a very different story.

> **The problem.** Insurance conversions were disproportionately low — despite having users with relevant use cases, real-time triggers (expiry, RC checks), and clear monetisation opportunity.

This wasn't just a funnel problem. It was a system-level inefficiency.

## The market We Were Operating In

The platform — a Vehicle Info market — served users who came with a clear, real-world intent: checking RC details, verifying ownership, reviewing insurance validity.

> **What this showed.** These are high-intent, real-world users — not passive browsers. Which makes them extremely valuable from a monetisation standpoint.

### The Disconnect

Even with strong relevance — insurance modules were visible, timing seemed logical, traffic was high — conversion didn't scale proportionally.

- Insurance modules were visible to the right audience

- User intent (vehicle expiry, RC checks) was contextually relevant

- Traffic volumes were substantial

- Yet conversion rates remained stubbornly flat

## Problem Statement: We Were Treating Every User the Same

Every user saw the same insurance CTA. Every user received similar nudges. Every user experienced identical flows — regardless of where they actually were in their buying path.

### Core Issues

### 1. No Intent Differentiation

We couldn't distinguish between casual users, curious users, and ready-to-buy users. All three received identical treatment.

### 2. Generic User Experience

A user with expiring insurance and a user casually browsing received the same experience. No personalisation. No urgency calibration.

### 3. Lost High-Intent Users

Even ready-to-convert users faced unnecessary friction — they weren't being prioritised or fast-tracked to conversion.

> **The takeaway.** We didn't have a traffic problem. We had an intent understanding problem.

## Key Insight: Intent is Behavioral, Not Declared

We observed a critical pattern: users don't randomly convert — they exhibit predictable behavioural signals beforehand.

High-Intent Signals

- Multiple searches in a session

- Longer session duration

- Insurance expiry within 30 days

- Repeated engagement across days

Low-Intent Signals

- Single interaction and exit

- Quick page bounce

- No CTA engagement

- No return visits

> **What this showed.** Intent is not declared — it is inferred from behaviour. This was the breakthrough that changed everything.

> If we can predict user intent using behavioural data, we can personalise their path and increase conversions at scale.

## Data Strategy: 50,000+ User Sessions

We didn't guess. We built a data collection pipeline that captured granular behavioural signals across 50,000+ user sessions — structured, cleaned, and ready for modelling.

### Behavioural Signals

- Search count per session

- Session duration (seconds)

- Scroll depth (%)

### Interaction Signals

- CTA click events

- Time on insurance page

- Form abandonment rate

### Contextual Signals

- Days to insurance expiry

- Vehicle age

- RC verification frequency

### Engagement Signals

- Push notification interaction

- Return visit frequency

- Cross-session behaviour

```
\{`Feature Vector: [Search_Count, Session_Time, Expiry_Days, CTA_Clicks, Return_Frequency] Derived Features: → Recency Score (how recently did the user engage?) → Urgency Score (how close is the expiry date?) → Engagement Index (breadth + depth of interaction) → Intent Velocity (speed of behaviour change over time)`\}
```

## ML Model & System Architecture

Logistic Regression

Baseline model — fast to train, interpretable, good for initial validation

Gradient Boosting (XGBoost)

Production model — best for structured data, interpretable feature importance, scalable

The model output was a single Intent Score (0–100) per user, computed in near real-time and used to drive personalisation decisions downstream.

## Learnings & Trade-offs

### Intent > Demographics

01

Traditional targeting by age, location, or device type was far less predictive than behavioural intent signals. A 45-year-old user who had checked insurance 3 times in a week was more valuable than a 25-year-old first-time visitor — regardless of demographic segment.

### Timing > Placement

02

The right message at the wrong moment is just noise. A high-intent user who sees an insurance CTA at 11pm after their third session converts at dramatically higher rates than the same user seeing the same CTA on their first page view.

### ML Needs Product Integration — Not Just a Score

03

An intent score sitting in a database is worthless. The real work was designing how the score influenced the product path — which required deep collaboration between data science and product design.

### Simplicity Wins in Production

04

The XGBoost model outperformed deep learning experiments not because it was more powerful — but because it was interpretable, debuggable, and reliable in production.

### Cold Start Problem

New users have no behavioural history. We handled this via heuristics — defaulting to medium-intent treatment until enough data accumulated.

### False Positives

Some users scored high but didn't convert. We tuned thresholds over multiple cycles and added contextual override rules.

### Over-personalisation Risk

Making UX too aggressive for high-intent users created pressure and reduced trust. We balanced urgency with reassurance.

## Future Scope

### Real-Time Scoring

Move from near-real-time to sub-second intent scoring at the moment of each user action.

### Deep Learning Models

Experiment with sequence models (LSTMs, Transformers) to capture longer behavioural patterns.

### Cross-Platform Signals

Incorporate signals from web, app, and notification interactions into a unified intent model.

### Reinforcement Learning

Let the system learn optimal messaging strategies directly from user response feedback loops.
